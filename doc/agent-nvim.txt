1. INTRODUCTION                                         *agent-nvim-introduction*

agent-nvim exposes a local MCP (Model Context Protocol) server over Streamable
HTTP. External AI agents (Claude Code, Goose, Kiro) connect to your running
Neovim instance and get full editor control: buffers, LSP, diagnostics,
navigation, terminals, and more.

The plugin also includes an ACP (Agent Client Protocol) chat UI that spawns
an agent process and gives it access back to Neovim's MCP tools.

==============================================================================
2. SETUP                                                       *agent-nvim-setup*

                                                             *agent-nvim.setup()*
>lua
    require("agent-nvim").setup({
      host = "127.0.0.1",           -- Listen address
      port = 0,                     -- 0 = kernel picks free port
      auto_start = true,            -- Start server on launch
      allow_code_execution = true,  -- Enable lua_exec, run, etc.
      review_edits = true,          -- Diff review before applying edits
      log_level = "info",           -- "debug", "info", "warning", "error"
      acp = {
        command = "goose",
        -- No --with-builtin: the agent gets ONLY the nvim tools via the MCP
        -- bridge (no developer/editor/shell builtins).
        args = { "acp" },
        env = {},
      },
      chat_height = 15,             -- Chat split height in lines
    })
<

When `port = 0`, each Neovim instance gets a unique port. Discover it with
|:McpStatus| or |:McpUrl|. A lockfile is written to
`$XDG_RUNTIME_DIR/agent-nvim/<pid>.json`.

3. COMMANDS                                                 *agent-nvim-commands*

:McpStart                                                          *:McpStart*
    Start the MCP server.

:McpStop                                                            *:McpStop*
    Stop the MCP server.

:McpStatus                                                        *:McpStatus*
    Show server status, URL, and active session count.

:McpUrl                                                              *:McpUrl*
    Print the server URL. Use `:McpUrl!` to copy to clipboard.

:McpSample [{text}]                                              *:McpSample*
    Send a sampling/createMessage request to the connected client.

:McpAutoComplete [{hint}]                                  *:McpAutoComplete*
    AI code completion at cursor. Supports a range for visual mode.

:AcpChat                                                            *:AcpChat*
    Open the ACP chat window. Creates a session if none exist.

:AcpChatToggle                                                *:AcpChatToggle*
    Toggle the chat window. Session stays alive when hidden.

:AcpChatNew                                                      *:AcpChatNew*
    Start a new chat session in a new buffer/process.

:AcpChatNext                                                    *:AcpChatNext*
    Switch to the next chat session.

:AcpChatPrev                                                    *:AcpChatPrev*
    Switch to the previous chat session.

:AcpChatCancel                                                *:AcpChatCancel*
    Cancel the in-flight turn of the active chat session.

:AcpChatClose                                                  *:AcpChatClose*
    Close the active chat session and terminate its agent.

:AcpChatList                                                    *:AcpChatList*
    List active chat sessions.

4. CHAT                                                         *agent-nvim-chat*

The chat UI is a bottom split buffer driven by ACP. The agent (default:
goose) has access to all Neovim MCP tools via the running HTTP server.

KEYBINDINGS (buffer-local to chat window):~

    <C-s>       Send the prompt (insert or normal mode)
    <CR>        Normal: focus the prompt. Insert: newline.
    ]b          Jump to next block (message, tool call, status)
    [b          Jump to previous block
    q           Hide the chat window
    <C-c>       Cancel the in-flight agent turn

GLOBAL KEYBINDINGS:~

    <leader>aa  Open the chat window
    <leader>at  Toggle the chat window

MULTILINE INPUT:~

The prompt region starts at the `> ` marker and extends to the end of the
buffer. Type normally — <CR> inserts newlines. Press <C-s> to send.

MULTIPLE SESSIONS:~

Use |:AcpChatNew| to create additional sessions. The winbar shows tabs:
`[1*] [2] [3]` — the active session is marked with `*`. Switch with
|:AcpChatNext|, |:AcpChatPrev|, or click the tab.

DISPLAY OPTIONS:~

The chat is terse by default: thinking/reasoning is hidden, agent messages
are rendered as markdown (headings, bold, inline code, and syntax-highlighted
fenced code blocks), and no emoji prefixes are shown. Configure via
|agent-nvim-setup|:

    setup({
      chat = {
        show_thinking = false,  -- show agent reasoning messages
        markdown = true,        -- treesitter markdown highlighting
        emoji = false,          -- emoji icons on status/tool/plan lines
        tool_cards = true,      -- ruled cards with arrows
        tool_preview_lines = 3, -- result lines shown inside a card
        card_arrows = true,     -- show the direction arrows
        rule_width = 40,        -- rule length in characters
        rule_indent = 2,        -- indent before each rule
        rule_char = "─",        -- rule character, "" disables
        prompt_gutter = "│",    -- gutter bar on your prompt
        step_separator = "─",   -- rule between turns and steps; "" disables
        live_markdown = true,   -- re-highlight while streaming
      },
    })

LINE CATEGORIES:~

Each kind of line has its own highlight group so the transcript is scannable.
The groups are linked to standard ones, so they follow your colorscheme:

    AgentNvimMeta        status/meta lines      -> Comment
    AgentNvimUser        your prompt            -> Title
    AgentNvimToolCall    "Tool Call:" lines     -> Function
    AgentNvimToolResult  "Tool Result:" lines   -> Comment
    AgentNvimToolError   failed results         -> DiagnosticError
    AgentNvimSeparator   the step rule          -> NonText

Define any of them yourself to override — your definition always wins:

    vim.api.nvim_set_hl(0, "AgentNvimUser", { link = "DiagnosticInfo" })

STREAMING:~

Agent text is written to the buffer raw as chunks arrive and markdown is
applied on top of it via extmarks, so the highlighting can be recomputed in
place without altering the text.

By default the message is re-highlighted as it streams (throttled). Set
|live_markdown = false| to leave the text raw while it arrives and apply
markdown once when the message is complete.

Setting |markdown = false| restores the legacy emoji-prefixed, plain-text
streaming. Setting |emoji = true| adds emoji icons to status, plan, and tool
lines (the message body stays raw markdown when markdown is enabled).

TOOL CALL OUTPUT:~

Each batch of tool calls renders as a ruled card, with ▸ marking calls going
out to a tool and ◂ marking results coming back (mirroring goose CLI):

    ─────────────────────────────────────────────────────
      ▸ read_file (path: src/main.rs, lines: 12-40)
      ▸ run (command: cargo test)
      ◂ run (result: exit_code: 0, stdout: test result: ok.)
        test result: ok. 412 passed
        running 412 tests
        ... (3 more lines)
      ◂ read_file (result: File: src/main.rs (562 lines total))
        File: src/main.rs (562 lines total)
          12	fn main() {
        ... (2 more lines)
    ─────────────────────────────────────────────────────

Calls issued together share one card — they are one batch of the agent's loop
— and their results append inside it as they arrive, so a batch completing out
of order still reads correctly. The closing rule is drawn once every call in
the batch has reported, marking the block's full extent. Each line is its own
jump target for |]b| and |[b|.

Arguments are summarized onto one line, preferring the key that identifies
what the call touches (`path`, `command`, `query`, ...) and skipping
source-text arguments such as `old_string` and `new_string`. Summaries and
previews are clipped to the window's text width, so no line ever wraps.
Failures render as `◂ tool (failed: <message>)`.

Set |tool_cards = false| for plain `Tool Call:` / `Tool Result:` lines.

LAYOUT, CARDS AND SEPARATORS:~

The transcript is built from FIXED-WIDTH, indented rules: a constant 40
characters indented by 2, not sized to the window. Resizing Neovim therefore
never leaves mismatched or wrapped rules behind.

      ────────────────────────────────────────
    │ you:
    │ Introduce yourself, then list the lua files.
    I'm goose, an open-source AI agent by AAIF — let me look at that directory.
      ────────────────────────────────────────
      ▸ shell (command: ls -la lua/agent-nvim/chat/)
      ◂ shell (result: total 8)
        total 8
        ... (4 more lines)
      ────────────────────────────────────────
    Here's what's there:
      ────────────────────────────────────────
    [turn end: end_turn]
      ────────────────────────────────────────

Rules mark the edges of each block:

  - Your prompt opens a card, marked with a │ gutter bar so it never reads as
    a continuation of the agent's prose. The bar is at a fixed column, so it
    survives a resize.
  - Each tool batch gets its own card, opened when the batch starts and closed
    once every call in it has reported.
  - The turn closes with a rule after the turn-end status line.

The turn's reasoning and message sit between the prompt's card and the first
tool card, which is why the agent's reply reads as belonging to your message.

With |tool_cards = false| there are no tool cards, so a rule is instead drawn at
each agent-loop step (a new assistant messageId), keeping the steps visible.

    setup({
      chat = {
        rule_width = 40,       -- rule length in characters
        rule_indent = 2,       -- indent before each rule
        rule_char = "─",       -- rule character, "" disables rules
        prompt_gutter = "│",   -- gutter bar on your prompt
      },
    })

5. AI ASSIST                                                  *agent-nvim-assist*

When a connected MCP client supports sampling, these keybindings activate:

    <leader>ac  Code completion (insert at cursor / replace selection)
    <leader>ae  Explain code
    <leader>af  Fix diagnostics
    <leader>ar  Refactor (prompts for instructions)
    <leader>av  Code review

These disappear when no capable client is connected.

6. TOOLS                                                       *agent-nvim-tools*

43 tools exposed via MCP `tools/list`. Major categories:

Buffers:      buffer_list, buffer_get_content, buffer_open, buffer_close,
              buffer_edit
Files:        read_file, edit_file, write_file, list_files, search_files, run
Navigation:   cursor_get, cursor_set, search, mark_set, mark_get
LSP:          lsp_goto_definition, lsp_references, lsp_hover, lsp_symbols,
              lsp_workspace_symbols, lsp_rename, lsp_code_actions
Quickfix:     quickfix_set, quickfix_get, loclist_set
Windows:      window_list, window_split, window_close, tab_list
Terminal:     terminal_open, terminal_send
Commands:     nvim_exec, nvim_eval, lua_exec, keymap_list, option_get,
              option_set, nvim_info, notify

==============================================================================
7. RESOURCES                                               *agent-nvim-resources*

Live editor state via MCP `resources/read`:

    nvim://buffers             All open buffers
    nvim://buffer/current      Current buffer contents
    nvim://buffer/{id}         Buffer by number
    nvim://selection           Visual selection
    nvim://cursor              Cursor with context
    nvim://diagnostics         All diagnostics
    nvim://symbols             Document symbols
    nvim://quickfix            Quickfix list
    nvim://git/status          Git branch and status

Resources support subscriptions — clients get notified when state changes.

8. HEALTH CHECK                                              *agent-nvim-health*

Run `:checkhealth agent-nvim` to see:

- Server status (running/stopped, URL, port)
- Active MCP sessions
- ACP agent availability (is `goose` in PATH?)
- Chat session state
